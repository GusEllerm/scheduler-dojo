Art 5 landed in two parts. **5a** (`1e10fcd`, shots in `c917927`) built the booth's front of house;
**5b** (this note, part b) is the booth's *voice*: the why-panel, step mode, reservations as cones,

## Part a — card slots, one-line editing, the editor hand-off (already committed)

The booth panel is four slot zones (`order, place, preempt, route` — `kata.ast.SLOTS` is ground
truth), a card rack (every module of `levels/reference_katas/` via `web/src/library.ts`), and the
one-line editor: the `key` line (else first statement) as an input with the **whole card** beside it
— "the card IS the kata". `serializeBooth` is the round-trip contract: filled slots print their
module verbatim in `SLOTS` order, so re-parsing reproduces the arrangement, and the only engine truth
applied is `check_kata` (an invalid edit gets a red chip and is never applied). Staffing a hand run
**records** the kata (no mid-run policy switch exists to call) and hands off to the full editor via
`saveBoothChoice` → `KataPlayOptions.initialKata`; `?city=2` was driven end to end in the acceptance
shot (`art5a-edit-line.png`).

## Part b — why-panel, step mode, cones, misfit, keyboard

Files: `web/src/campus-why.ts` (new), `web/src/campus-play.ts`, `web/src/campus.ts` (`Cone.from`),
`web/src/campus-render.ts` (countdown bar span), `web/src/tutorial.ts`, `web/src/style.css`. Zero
Python: `uv run pytest -q` stays at 312 and no golden moved.

- **Why-panel**: a collapsible `<details>` in the campus stage, fed by `start(trace=24)` on live
  campus runs (only there — `run`, `hand_start` and the CLI still pay nothing). Rows keyed by the
  record's `seq`, appended only when new; `role="log"` polite. An order key is named by comparing its
  first component to that vehicle's own engine facts, so "shortest first" is what the key
  *demonstrates*; anything else says "an order key of its own". A `fallback` record prints the plain
  words **and** the engine's code (`no fit — kept FIFO order (no_nodes)`). Owner color rides on a bar,
  not the text — palette tokens are tuned for the canvas, not 12 px text.
- **Step mode**: `Step ▸` in the campus control row (live runs only; hand hides it, its clock is
  `Time ▶`). Pause the rAF loop, then `step_n(handle, 1)` per press = **one event batch** (every event
  at one timestamp + its one decision — the unit trace records come from), one `step_once`, one why
  refresh, one settled frame. `Resume` re-bases the wall clock. `set_mode "step"` routes here.
- **Cones**: engine cones are `reserve` *intents* — the snapshot names no bays, so they hang on the
  vehicle and never on a guessed bay. The hand "Cone it" button draws a **viewer-side** cone over the
  bays the engine's own FIFO hint (`suggestions`) would give the selected vehicle (the player's staged
  bays win at the right size), counting down on sim time and pruned inside `step_once`. It books
  nothing and says so in the button title, the toast and this note — inventing a hand-mode `reserve`
  would be inventing engine behavior.
- **Misfit feedback**: `hand_place`'s `PolicyError` code maps to a campus sentence (lowercase codes:
  `no_nodes`, `mismatch`, `already_running`, `deps_unmet`, `unknown_job`), red edge + one shake on the
  hand bar (skipped outright under reduced motion, red edge only) and a polite reason line under it.
- **Keyboard**: the hand canvas is `tabindex="0"` with the keys in its aria-label — arrows cycle the
  vehicle in engine road order then slide its bay **window** (adjacency is the lesson), Enter parks
  (the engine decides), Esc clears; state changes go through the stage's existing polite regions.

### Two bugs the acceptance drive found (both pre-existing, one repo-relevant)

1. **The locally staged wheel predated `df59b32`** — `web/public/wheels/*.whl` was built before the
   trace plumbing landed, so `step_n`/`step_until` returned no `trace` array and the why-panel looked
   dead. CI and Pages run `scripts/build_wheel.sh`, so the deployed site was never affected; the fix
   here was `bash scripts/build_wheel.sh && npm run build`. Anyone verifying trace work locally should
   rebuild the wheel first.
2. **`first_time: pressure_moved` is unreachable on a hand campus with rings undeclared.** No level
   declares `pressure` yet (Art 6 puts rings in the cities), and an **unparked** hand campus emits no
   FINISH events, so its clock stops at its last arrival — ~13.4 ks on level 3, inside the runner's
   `2 x stride` (34 285 s) stall watchdog. City 3's cone beat could therefore only be reached by a
   timeout that never came. [agent decision] the runner now fires `pressure_moved` from the same
   engine facts `behind` already reads **only when the snapshot carries no rings at all** — the same
   documented "derive until the engine lands it" stance as `placed_total`/`week`. Rejected: editing
   `city3.json`'s `when` to `behind` (the checker keeps `behind` inside `when.all` only) and adding a
   `pressure` block to the city patch (whitelisted fields only + a Python edit + a golden move).
   Retire the fallback when Art 6 puts `pressure` in the city levels.
