# 2026-10-02 Phase 2 Art 6 — weeks, offers as buildings, free grants

Art 6 lands in two parts. The **engine slice** (`6f50c02`: `BUILDINGS`, `offer_accept`,
`progression_grant`, save v3 `weeks`, city 4–9 scripts) was already shipped and noted in
[[Modules/scheduler_dojo-progression]]. **This note is part a — the UI half**: the week-end freeze,
the ONE offers overlay, building sprites with first-use guidance, and the tutorial's free grants.
Mapping authority stays in [[Concepts/Campus]] (see its "Week end and buildings on the campus"
section); beat grammar in [[Concepts/Tutorial]]; dialog/hatch channels in [[Concepts/Accessibility]].

## What shipped

- **`web/src/offers.ts`** — the single offers overlay both the campus and the tutorial open:
  each offer rendered as an inspectable *building* (name + blurb + "`reserve` tier of Kata"
  unlocks line, all from `progression_view.upgrades` — the same `BUILDINGS` table the sprites
  read). `onTake` verdicts land in a `role="status"` note; a successful take closes the panel.
- **`web/src/campus-play.ts`** — `weekTick` (engine `calendar_at` boundary + snapshot `week`),
  the traffic freeze in BOTH live and hand modes, `openWeekOffers`/`takeOffer`/`resolveWeek`,
  the pending-offers hatch, `refreshBuildings` → `LayoutInput.buildings`, `revealBuilding` as a
  real reveal (dim `?` → sprite + CSS pop), `tutorialManaged(on)`, first-use guidance gated by
  `buildingSeen:<id>` prefs, and `pendingFinish` so a run that drains at the boundary lands its
  result only after the choice. Everything is inert when `manual: true` (the visual harness),
  which is why `campus_visual` re-renders level1/level3 with **zero PNG diff** against the Art 3
  baselines.
- **`web/src/campus.ts` / `campus-render.ts` / `campus-hit.ts`** — `BuildingSprite` layout by
  engine anchor (locker by the lots, scale hut + truck pad on the road kerb, board by the
  neighbourhoods, gate at the edge), flat token sprites, building hit → detail card
  (`name — blurb + buildingHint`).
- **`web/src/tutorial.ts`** — `offer_upgrade {forced}` → the FREE `progression_grant` (the
  "not buyable" purchase message is gone); `{pick_of: 2}` → the campus's own
  `openWeekOffers` at the boundary week; gate/wait release on `week_end` (see
  [[Concepts/Tutorial]] — the hand clock stops at its last arrival, so an unreachable gate would
  strand the script); `tutorialManaged` hand-off on attach/finish.
- **`web/src/bridge.ts` / `progression.ts`** — `offerAccept`/`progressionGrant` wrappers
  (dispatch `offer_accept` / `progression_grant`), `grant`/`acceptOffer` store helpers, the
  `weeks` field on `ProgressionState`, `buildings` on `ProgressionView`.

## Decisions

- **The freeze fires the `week_end` event.** Hand snapshots pin `week: 1` (`hand_start`/`hand_tick`
  don't register the level for the snapshot calendar), and the arrival stream can end before the
  horizon, so the runner's old `now >= duration` clause alone would miss the boundary while the
  campus stood frozen. The freeze IS the engine boundary, so it announces it (event dedupe makes
  the two paths harmless together). Alternative rejected: a Python change to hand snapshots
  ("Python untouched" this slice).
- **Week end releases pending tutorial waits** — `[agent decision]`, rationale in
  [[Concepts/Tutorial]].
- **`pendingFinish`**: a live run that reaches the boundary and `done` in the same batch shows
  offers first, then the result — "never end a turn broken".
