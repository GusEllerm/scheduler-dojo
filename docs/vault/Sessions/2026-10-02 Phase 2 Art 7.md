## What shipped

- **`web/src/review.ts`** — the ONE review panel. Opens itself at the end of a campus run (live,
  hand, endless) and is offered as a "Review ▸" button (`mountReviewButton`) on every other
  finished run's readout, so no modal fires the instant a watch page loads. It decides nothing and
  calls nothing: the strip is the phase-one `mountTimeline` mounted **paused** (dark cells are the
  idle gaps), the share rows are the rail's `fairnessShares` re-rendered from the finished job list,
  and the mistake lines are *derived* — timeouts, never-parked, starved shares, and the overflow
  line. `mistakesOf` aggregates per (user, kind) so an endless overflow that strands hundreds of
  jobs is one calm line, not a thousand.
- **`web/src/campus-play.ts`** — `endlessMode` (recognized by `id === "endless"`): a **literal**
  86,400 s / 7-day calendar (cities keep the compressed one-week mapping), week boundaries that
  advance the clock but never freeze (the offer table is keyed by integer city, there is no endless
  key), the `afterDone` → `overflowMoment` hold (one ring-pulse flash of the overflowing neighbour's
  road vehicles, `.campus-overflow-flash`, ~0.9 s; the visual harness never flashes, reduced motion
  finishes instantly), and the `seekRender` done-routing through `afterDone`. The endless campus
  also passes `simRate` (below).
- **`web/src/main.ts`** — the Endless chip launches the live endless run (`bridge.endlessLevel` of
  `ENDLESS_GROWTH` at the save's seed, booth staffed with the engine's `shortest_first`), a "New
  seed ▸" reroll (a UI-side LCG step from the shown integer — `Math.random` never touches a
  sim-bound stream, [[Determinism]]), the best score (`prefs.endlessBest`, days first / served as
  tie-break) surfaced on the chip, and `openReviewPanel` wired into `onFinish` for both endless and
  city runs (a script owns its own ending, so it is skipped while one is on stage).
- **`web/src/style.css`** — the review overlay/panel/mistake-row/overflow-flash rules (fixed
  overlay so the panel works in every mode's chrome; the share rows reuse the rail's classes).

## Two client bugs the exercise caught (not in the previous builder's claims)

1. **`fairnessShares` NaN in the review** — every share read "0% · NaNhNaNm parked" and *every*
   neighbour was flagged `starved`. Cause: **Pyodide's `toJs` turns Python `None` into
   `undefined`**, but `fairnessShares` only treats `null` as never-started, so an unfinished endless
   job poisoned every share sum with NaN. Phase one already guards this exact quirk (`main.ts:982`,
   `timeline.ts:89`); the review's `shareJobs` now null-normalizes `start`/`end`. (The city review
   never showed it because its run had no never-started job.)
2. **`step_result` reported the wrong policy** — the review meta said `fifo` for a run the campus
   started with `shortest_first`, because `step_result` read `lvl.default_policy` (the endless level
   has none). `bridge.start` now records the policy it actually started with (`_SESSION_POLICIES`)
   and `step_result` reports it, mirroring what `run()` already did. Verified: the review now reads
   `seed 20261002 · shortest_first`.

## The "step_until stall" — what it actually was

An earlier investigation of the endless campus freezing at `t=1080` under `seekRender` after a
pause chased an app-side race. There was none. It was two things: (1) a **driver artifact** —
playwright silently does *not* invoke a block/expression-bodied `async (t) => …` **string** passed
to `page.evaluate` (it returns `undefined`), so the first pass's "frozen" seeks never ran at all;
every seek here is a real function. (2) the **real pin**, an engine one: a driver whose step target
sat below `t0 + horizon` on a t0>0 level pinned the clock forever. The engine half was fixed in
`4cab6b3` (stepped runs END at the horizon, done fires on the stop frame, snapshots publish
`horizon_end`). This slice added the two ends that fix needs to actually hold on the campus:

- **Client** (`simTarget`): the step-target cap is now `max(duration + 2·step, horizon_end)`, so it
  can never sit below the horizon.
- **Engine** (`_advance`, `4cab6b3` follow-up): the *empty-heap* done path now lands the observed
  clock on `t0 + horizon` before reporting done (the `next-event-past-until` path already did). A
  run whose **last event predates the horizon** — a normal city run — otherwise reported done with
  `now` stuck short of the boundary, and the campus week-end freeze watches `now`, so the run ended
  *without ever offering its week end*. This was the real blocker for the level3 city review case;
  city 3 now freezes at the horizon, takes an offer, then reviews. Test:
  `test_empty_heap_done_lands_the_clock_on_the_horizon` (+1 → **324 passed**).

## Endless pacing (`simRate`) — an [agent decision]

The watch plan's 1× cadence (`step × 60` ≈ 64,800 sim-s/s) is tuned for a compressed city week but
crushes a LITERAL 30-day endless stream into ~40 s of watching — the ramp never reads as a ramp and
a "week 2" screenshot/fps sample can't catch a live run. The endless campus passes a `simRate`
override = **3,600 sim-s per wall-second** (one literal day ≈ 24 s, a calm watchable run). The
stream and its hashes are untouched; city pacing is untouched (the override is endless-only). The
week-thickening then arrives on a schedule the rig can wait on.
