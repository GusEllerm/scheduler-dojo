# 2026-10-02 Phase 2 Art 3 — the campus renderer lives

[agent decision] **Art 3 = the live campus view wired to the stepping API**, keeping the timeline as the
post-run review (per [[Concepts/Campus]] §2.6): a 4th mode "Campus (live)" builds a pure
`buildScene` projection of each snapshot (`web/src/campus.ts`), painted by `CampusRenderer`
(`web/src/campus-render.ts`, built by a sub-agent from the token palette), hit-tested for hover detail
cards (`web/src/campus-hit.ts`), driven by `CampusPlay` (`web/src/campus-play.ts`), which owns the rAF
loop, wall-clock pacing, pause/speed, and `seekRender(t)` for the screenshot harness
(`web/campus-harness.html`).

The integration was a bug-hunt; every fix is a real lesson:

- **The engine clock froze between events.** `run_until(t)` only moved `now` *to* event times, so a
  stepped view idled at the last event forever (`t=2m` for seconds of wall time). Fixed in
  `_advance_clock_to`: the observed clock lands on the step horizon; `_finished` on an empty heap only
  when `until` cannot hide future events (a step at `t=137` with a heap empty-to-20000 had ended the
  whole run early). Trajectory-neutral — goldens untouched.
- **Wall-clock-anchored pacing**, not per-frame stride: `target = startSim + wall x step x 60 x speed`,
  with a `rebase()` (reset wall-zero to `now`) at start, on *resume*, and on *speed change* — without
  it a slowdown rewound the target below `now` and the clock crawled at +1/frame.
- **The clock is integer.** The wall mapping produced float sim-times; both sides hardened
  (`Math.floor` before the bridge, `run_until` clamps a float `t`). See [[Concepts/Determinism]].
- **Vehicle state is derived from the clock, never from the job map.** The union view carries entries
  across steps; an old `state` field said "queued" to finished jobs forever. `buildScene` now decides
  unseen → running → done → queued from `now` alone.
- **Snapshots don't carry the future**: `_snapshot.unseen` lists jobs whose submit is still ahead, so
  the campus can show all neighbourhoods/vehicles from first principles.
- Dev-server drift (stale wheel, un-imported `tokens.css`, canvas sized after renderer construction,
  `step_result` missing `score`) each got a permanent fix, not a workaround.

Acceptance: `CampusPlay.fps()` samples the render loop over ~2 s; the harness runs nine cities and the
screenshot path is the visual baseline. Screenshot-verified: bays fill with owner-colored run bars,
vehicles queue on the road, sun tracks the day, patience rings draw around neighbourhoods.
